## 🧪 Ce am exersat în laborator

În cadrul laboratorului dedicat managementului codului, am studiat rolul sistemelor de control al versiunilor și integrarea Git cu GitHub și Visual Studio Code.

### Noțiuni și operații Git

| Comandă | Utilizare |
|---|---|
| `git init` | Inițializează un repository Git local. |
| `git status` | Afișează starea fișierelor și modificările detectate. |
| `git add README.md` | Adaugă fișierul indicat în Staging Area. |
| `git add .` | Pregătește modificările din directorul curent pentru commit. |
| `git commit -m "mesaj"` | Înregistrează modificările pregătite într-un commit. |
| `git log` | Afișează istoricul commit-urilor. |
| `git remote add origin [URL]` | Adaugă o adresă remote pentru repository. |
| `git push` | Trimite commit-urile locale către repository-ul la distanță. |
| `git pull` | Preia și integrează modificările din repository-ul la distanță. |

Am studiat, de asemenea, conceptele de **repository**, **Staging Area**, **commit**, **remote**, **branch**, **HEAD** și rolul ramurii principale (`main` sau `master`). Am explorat și utilizarea secțiunii **Source Control** din Visual Studio Code pentru gestionarea modificărilor fără a introduce fiecare comandă manual.

### Flux simplificat de lucru

```text
Modific fișierele proiectului
          |
          v
    git status
          |
          v
       git add
          |
          v
      git commit
          |
          v
       git push
          |
          v
  Repository actualizat pe GitHub
```

Pentru actualizarea copiei locale cu schimbările existente pe server se poate utiliza `git pull`.
